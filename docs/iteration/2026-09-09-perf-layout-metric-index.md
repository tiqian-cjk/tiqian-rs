# 2026-09-09 布局度量索引性能优化

## 目标与证据

用户在上游同步后观察到性能下降。当前未提交同步增加最终结果的派生查询，
既有布局路径只涉及查询辅助函数可见性变化；release 配置增加 debug 信息。
当前无采样基准的 672/360/960 宽度 layout median 为 2.404/2.480/2.385 ms，
p95 为 2.527/2.584/2.510 ms，未重现相对上一轮记录的核心布局回退。

新火焰图为 2026-09-09 11:25:36 的无界面基准采样：布局入口 66,463 个样本，
preparation 24,700，finish 23,972，planning 14,899，debug assembly 6,512。
父子样本重叠，不能相加或直接换算加速比例。
planning 度量构造闭包为 4,820 个样本，cluster 度量映射闭包为 1,707，
后者的 decision clone 子调用为 1,687。源码确认映射为每个 cluster 深复制所属
字体段的完整度量 decision，消费者只读取其 layout metrics。

## 范围与设计

将 planning 的 `metric_decision_by_range` 替换为
`metric_decision_index_by_range: HashMap<TextRange, usize>`，保存原有
`metric_decisions` 向量的下标。finish 查询下标后借用原 decision。
保留原有 containing-items 匹配、缺失处理、重复键覆盖和计算顺序。
复杂度保持线性构建与平均常数时间查询，省去逐 cluster 的文本、字体请求和
完整 decision 分配与复制。

阶段结果字段名称与类型改变；主排版接口、Unicode scalar coordinate、
布局几何和完整 debug 输出不变。无新布局规则或架构取舍，无需更新 ADR、
关键差异或上游同步终点。用户同步代码与新火焰图保持原状。

## 验证与回滚

保留改前 release 可执行文件，在相同参数下交替运行改前和改后基准，
检查三种宽度的 median、p95 和工作量。运行完整 cargo test（含 fixture golden），
不更新 golden；检查编辑器诊断、目标 diff 与文档风格。
如行为变化或性能退化，恢复原字段、clone 构造与消费者即可。

## 实施结果

两个布局文件已完成下标映射替换。完整 `cargo test --quiet` 通过：19 项单元测试、
1 项独立集成测试、1,349 项主集成测试，含 fixture golden，未更新预期。
仅出现既有未使用字段警告。

使用同一 release 配置保留改前程序，按 A/B、B/A、A/B 顺序运行六次默认基准。
每次 600 页、28,200 次布局，程序内置的行数、cluster 和 glyph 工作量检查均通过。
